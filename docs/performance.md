# 撮合与恢复性能基线

2026-11-26，业务基线 `1ed4c1a` 加本次未提交的基准代码；Windows、Intel i5-12500H（12 核/16 线程）、Temurin 17.0.18、Maven 3.9.16，单 JVM、单执行线程、堆 512 MiB。未对机器做负载或频率控制。

## 复现

从仓库根目录运行：

```powershell
mvn -B -ntp -f build/pom.xml -pl ../trading-engine -am '-Dtest=SecuritiesBenchmarkTest' '-Dsurefire.failIfNoSpecifiedTests=false' '-Dsecurities.benchmark=true' '-DargLine=-Xms512m -Xmx512m' test
```

输出六行 `BENCH`。两个场景分别常驻 0、250 张不参与撮合的低价买单；每轮执行 3,000 个预生成的事件，包含 1,500 对同价买卖。每个场景两轮预热后三轮采样，交替场景顺序。吞吐按事件数除以核心执行计时之和；分位采用 nearest-rank。校验、输入构造与抓取快照不计入实时执行计时。

## 实测结果

| 常驻挂单 | 轮次 | 事件/秒 | P95 (μs) | P99 (μs) | 全量重放 (ms) | 内存快照恢复 + 300 个后缀事件 (ms) |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 1 | 336,074.2 | 5.10 | 16.40 | 8.60 | 0.77 |
| 0 | 2 | 392,172.2 | 3.50 | 6.90 | 6.61 | 0.74 |
| 0 | 3 | 233,735.9 | 5.50 | 10.50 | 7.87 | 0.83 |
| 250 | 1 | 10,141.2 | 147.50 | 200.70 | 312.72 | 29.38 |
| 250 | 2 | 11,142.4 | 142.20 | 215.50 | 300.49 | 27.48 |
| 250 | 3 | 8,513.7 | 239.70 | 359.60 | 333.57 | 29.28 |

三轮中位数：0/250 挂单的事件吞吐分别为 336,074/10,141；P99 分别为 10.50/215.50 μs；全量重放为 7.87/312.72 ms，快照加载加后缀为 0.77/29.28 ms。全量重放分别包括 3,002、3,252 个事件。两种恢复均与实时执行的最终快照逐项相等。

常驻挂单明显影响本次内核用例的耗时。状态复制和校验均在被测区间，**不能仅靠本次对比确认各自占比**；优化前可用 JFR 进一步归因。

## 未包含

本结果不是 HTTP QPS、最大承载量或生产容量；不含 HTTP、Kafka、MySQL 事务、快照磁盘 I/O、Redis、网络或并发排队，也不是优化前后对比。没有测端到端性能。下一轮应在单独测试环境用固定并发和持续时间，分别记录 HTTP 受理、终态确认、事件积压/追赶、错误率及成功成交数；不能用受理延迟代替成交延迟。
